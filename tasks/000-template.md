# Task: 제목

## Goal

이번 작업의 목표와 완료 조건을 적는다.

## Context

왜 필요한 작업인가? 사용자 또는 프로젝트 관점의 문제를 적는다.

## Relevant Knowledge

읽어야 할 context/domain/ADR 문서와 관련 task를 연결한다.

## Current State

작업 전 코드, 문서, Git 상태와 확인된 제약을 적는다.

## Options Considered

구현 방법 후보와 각 후보의 장점, 단점과 위험을 적는다.

## Plan

선택한 방법과 변경 범위, 구현·검증 순서를 적는다.

## Changes

실제 변경한 파일과 동작을 적는다. 계획과 달라졌다면 이유도 적는다.

## Problems Encountered

발생한 오류, 실패한 시도나 예상 밖의 문제를 적는다.

## Resolution

문제의 원인과 해결 방법을 적는다. 해결하지 못했다면 현재 blocker를 명시한다.

## Verification

실행한 typecheck, lint, test, API 확인과 수동 검증의 명령·결과를 적는다.

## Diff Review

diff에서 확인한 핵심 변경, 예상 밖 변경 여부와 사용자가 볼 부분을 적는다.

## Follow-up

이번 범위에 포함하지 않은 다음 작업과 남은 위험을 적는다.

## Lessons Learned

이번 작업에서 배운 기술 또는 작업 방식의 교훈을 적는다.
