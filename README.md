# Phyto Shop

TypeScript, Next.js, NestJS와 Vercel을 사용해 만드는 학습용 파이토쇼핑몰입니다.

이 프로젝트의 목적은 완성도 높은 쇼핑몰을 빠르게 출시하는 것이 아닙니다. 작은 쇼핑몰을 직접 구현하면서 지정된 기술 스택과 AI 협업 개발 방식에 익숙해지고, 그 과정에서 내린 결정과 시행착오를 Git 기록으로 남기는 것이 핵심입니다.

## 과제 목표

- TypeScript 7, Next.js 16, NestJS의 역할과 연결 방식을 익힌다.
- 프런트엔드, 백엔드, 데이터베이스, 배포로 이어지는 전체 웹 개발 흐름을 경험한다.
- Orca에서 작업별 Git worktree를 만들고, 각 작업을 서로 격리해서 진행한다.
- VS Code에서 코드를 직접 읽고 수정하며 디버깅한다.
- Codex를 단순 코드 생성기가 아니라 설계 검토, 구현, 테스트, 리뷰를 돕는 협업 도구로 사용한다.
- 구현 전에 가능한 방법과 장단점을 검토하고, 선택한 방법과 이유를 기록한다.
- 작업 중 발생한 문제, 실패한 시도, 원인, 해결 방법과 개선점을 남긴다.
- 대화가 바뀌어도 프로젝트 문맥이 유실되지 않도록 LLM Wiki 형태로 도메인 지식을 관리한다.
- Vercel에 애플리케이션을 배포해 로컬 개발부터 배포까지의 흐름을 익힌다.

## 만들어 볼 결과물

파이토 관련 상품을 판매하는 형태의 작은 쇼핑몰을 만든다. 실제 쇼핑몰의 구성과 사용자 경험을 참고할 수 있지만, 사용한 이미지와 자료의 출처 및 사용 여부는 기록한다.

예정된 주요 기능은 다음과 같다.

- 상품 목록과 상품 상세 화면
- 장바구니와 주문서
- 주문 생성 및 데이터베이스 저장
- 결제 전후의 주문·결제 상태 확인
- Toss Payments 테스트 환경 연결
- 결제 성공 및 실패 처리
- Vercel Preview와 배포 환경 구성

기능의 개수보다 각 기능이 프런트엔드, 백엔드, 데이터베이스 사이에서 어떻게 동작하는지 이해하는 것을 우선한다.

## 기술 스택

| 영역 | 기술 |
| --- | --- |
| 언어 | TypeScript 7 |
| 프런트엔드 | Next.js 16 |
| 백엔드 | NestJS |
| 배포 | Vercel |
| 결제 실습 | Toss Payments 테스트 환경 |
| 개발 도구 | Orca, VS Code, Codex |
| 작업 방식 | Git, Git worktree |
| 데이터베이스 | 설계 단계에서 비교 후 결정 |

## 작업 원칙

1. `main` 브랜치에서 직접 기능을 개발하지 않는다.
2. 하나의 기능이나 실험마다 Orca에서 별도의 Git worktree를 만든다.
3. 구현 전에 요구사항, 선택지, 예상되는 데이터 흐름과 완료 조건을 작성한다.
4. Codex가 만든 코드를 그대로 받아들이지 않고 VS Code와 diff에서 직접 검토한다.
5. 테스트와 실행 결과를 확인한 뒤 커밋한다.
6. 시행착오와 중요한 기술 결정은 코드와 함께 저장소에 기록한다.
7. 작업을 끝낼 때 LLM Wiki의 도메인 지식이 여전히 현재 코드와 일치하는지 확인한다.

## 결제 실습에서 확인할 내용

실제 결제나 운영용 키 발급은 목표가 아니다. Toss Payments의 테스트 키와 테스트 결제 흐름을 사용해 SDK와 서버 승인 과정을 연결한다.

특히 결제 버튼을 누른 뒤 다음 내용을 관찰하고 기록한다.

- 주문은 어느 시점에 생성되는가?
- 결제 요청 전후로 데이터베이스의 주문 상태는 어떻게 바뀌는가?
- 결제 성공과 실패는 각각 어떤 상태로 저장되는가?
- 클라이언트가 보낸 결제 금액을 서버에서 어떻게 검증하는가?
- 같은 승인 요청이 반복될 때 데이터가 중복 변경되지 않게 하려면 어떻게 해야 하는가?

## 과정 기록

저장소에는 최종 코드뿐 아니라 다음 자료도 함께 남긴다.

- 기능별 작업 계획과 완료 조건
- 기술 선택의 대안과 결정 이유
- 주문 및 결제 도메인 용어와 상태 변화
- 실패한 시도와 오류 메시지
- 문제의 원인과 해결 과정
- 테스트 및 검증 결과
- 작업 후 회고와 다음 개선 사항

이 기록들은 Codex가 다음 작업에서 읽을 수 있는 프로젝트 문맥이자, 과제에서 개발 과정을 설명할 수 있는 근거로 사용한다.

## 완료 기준

- 모든 기능 작업이 Git worktree 기반으로 수행되었다.
- Next.js 프런트엔드와 NestJS 백엔드가 연결되어 있다.
- 주문 및 결제 상태가 데이터베이스에 저장되고 그 변화를 확인할 수 있다.
- Toss Payments 테스트 결제 흐름이 연결되어 있다.
- Vercel에서 실행 가능한 배포 결과를 확인할 수 있다.
- 주요 기술 결정과 시행착오가 커밋 및 문서에 남아 있다.
- 새로운 Codex 세션에서도 저장소 문서만 읽고 프로젝트의 현재 맥락을 파악할 수 있다.

## 범위 밖의 목표

- 실제 고객을 대상으로 한 운영용 결제
- 실물 상품의 배송 및 정산
- 운영 수준의 모든 쇼핑몰 기능
- 기존 쇼핑몰을 그대로 복제하는 것

결과물의 규모보다 기술을 선택하고 연결하고 검증한 과정을 명확히 설명할 수 있는 상태를 목표로 한다.
